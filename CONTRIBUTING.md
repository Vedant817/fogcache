# Contributing to FogCache

FogCache is a monorepo (ADR-0001). Every module follows the same engineering
baseline defined in the parent POM; `mvn verify` is the single command that
proves a change is shippable.

## Prerequisites

- JDK 21 (Temurin recommended) — the build enforces `[21,22)`
- Maven 3.9+ (use the wrapper `./mvnw`, no local install needed)
- Docker Desktop (optional for development; required for the Testcontainers
  smoke tests that run the `grafana/otel-lgtm` stack). Without Docker, those
  tests degrade gracefully to plain context loads, so `verify` stays green.
- Node.js (only to lint the OpenAPI contracts via `npx @redocly/cli`)

## Building

```bash
./mvnw verify                # everything: gates, tests, packaging
./mvnw verify -DskipTests    # gates + packaging only
./mvnw -pl fogcache-common test   # a single module
./mvnw spotless:apply        # fix formatting before committing
./mvnw -Psecurity verify     # OWASP dependency-check (CVSS >= 7 fails)
```

The wrapper is `mvnw.cmd` on Windows.

## Quality gates (all bound to `verify`)

| Gate | Tool | Fails when |
|---|---|---|
| Build rules | enforcer | Maven < 3.9, JDK outside 21, dependency version conflicts/convergence, duplicate versions, banned deps (`junit:junit`, vintage engine) |
| Formatting | spotless (google-java-format) | Sources or poms are not formatted — run `spotless:apply` |
| Style | checkstyle (google_checks.xml) | Any violation in main or test sources; suppressions in `config/checkstyle/suppressions.xml` |
| Static analysis | spotbugs | Bugs above Medium threshold; exclusions in `config/spotbugs/exclude.xml` |
| Coverage | jacoco | Line < 60% or branch < 40% on modules with the gate enabled (`jacoco.skip=false`) |
| Git metadata | git-commit-id | — (writes `git.properties` for actuator `/info`) |

Modules without unit tests yet (service scaffolds, contracts, integration
tests) set `<jacoco.skip>true</jacoco.skip>`. **When a milestone adds real
unit tests to a module, remove that property** — the gate must be on.

## Dependency hygiene

- Version numbers live in exactly two places: the parent POM properties and
  `fogcache-bom` (for dependencies) / parent `pluginManagement` (for plugins).
- Never put a version in a module pom.
- Spring-managed artifacts (spring, reactor, testcontainers, ...) are owned by
  `spring-boot-dependencies` and must not be pinned in the BOM.
- Check for updates with `./mvnw versions:display-dependency-updates`.

## Contracts

- gRPC: edit `fogcache-contracts/src/main/proto/*.proto`; Java code is
  generated by the build (protoc 4.x) into `target/generated-sources` — never
  commit generated code.
- OpenAPI: edit `fogcache-contracts/src/main/resources/openapi/*.yaml`; CI
  lints them with redocly.
- Every contract change must update the matching ADR and
  `docs/architecture/contract-conventions.md` (see `docs/README.md`).

## Commit conventions

- One logical change per commit; each milestone's issues map to commits with
  a `feat:`, `fix:`, `docs:`, `chore:`, or `test:` prefix.
- Rebase onto `master`; keep history linear. Update the issue in Linear and
  link it in the commit body where it exists.

## CI

`.github/workflows/ci.yml` runs on every push/PR to `master`:

1. `build` — full `mvn verify`, redocly contract lint, CycloneDX aggregate
   SBOM (uploaded as an artifact).
2. `dependency-check` — OWASP NVD scan, CVSS ≥ 7 fails; feed flakiness does
   not block the main build (findings tracked separately).

## Documentation

All product/architecture docs live under `docs/` (index: `docs/README.md`).
Docs change via PRs that also update the corresponding ADR/contract.
