# ADR-0007 — Python training pipeline with ONNX inference in Spring Boot

Status: Accepted · Date: 2026-08-07 · Issue: VED-54

## Context

Hot-key classification and demand prediction need model development (offline experimentation) but inference must run inside the Java analytics service with low latency and reproducible feature semantics.

## Decision

- Training lives in `fogcache-model-training` (Python, scikit-learn/LightGBM): dataset validation, feature generation from the same feature-schema contract, baseline comparison (last-value, EMA, seasonal, Markov), training, calibration, evaluation, and ONNX export.
- Inference runs in `fogcache-analytics-service` via ONNX Runtime (JNI), with a versioned feature schema shared with training (Protobuf message reused as feature record).
- A **deterministic rule-based classifier remains the default path**; ML models run in shadow mode first and are promoted only after measurable uplift vs the rule baseline (see `slos.md` §5). Kill switches disable ML/prefetch at runtime.
- Model registry: artifacts stored in S3-compatible storage with version + checksum + feature-schema compatibility; rollback = re-point to previous version.

## Alternatives considered

- Python inference service (model server): rejected — adds a network hop and an extra runtime to operate; ONNX Runtime in-process meets latency needs.
- Java-only training: rejected — the scikit-learn/LightGBM ecosystem is materially stronger for this workload.

## Consequences

+ Best-of-both: strong training tooling, in-process inference, rule fallback always available.
− ONNX Runtime native dependency must be pinned per platform; mitigated by containerized deployment (milestone 13).
− Feature drift between training and serving is a live risk; mitigated by schema-versioned feature records and shadow-mode validation.

## Rollback/migration

Rule-based classifier is always deployable (kill switch); model rollback = point registry to previous artifact version with the same feature schema; schema incompatibility blocks promotion.
